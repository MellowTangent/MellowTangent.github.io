- **Box Info:** 
	- Tier: 0
	- Name: Dancing
	- OS: Windows
	- Difficulty: Very Easy
- **Enumeration:** The first thing we do is run a scan on the target computer using Nmap this has become the standard procedure for these kinds of boxes. 
  ![](/assets/img/dancing/nmap-scan.png)
  
  The scan reveals several services on the target machine. The service we want to target is SMB (Server Message Block) and it uses port 445 over TCP. Thus, we can ignore the other services and we can focus on the service called `microsoft-ds`. 
  
- **Access:** After doing a quick search on DuckDuckGo I find what command options I can use with the `smbclient` command and one stands out to me.  
  ![](/assets/img/dancing/command-search.png)
  
  The `-L` switch combined with `-N` will allow us to list the shares without prompting us for a password but I still mess around with the switches to see what they do. As the saying goes "trust but verify". As expected `-L` switch without `-N` allows us to list the shares but it prompts for a password. Lucky for us there is no password and we simply press `ENTER` on the blank password field. 
  ![](/assets/img/dancing/testing-command1.png)
  
  Then I test `-L` + `-N` and as expected we get a list of the shares without a password prompt.
  ![](/assets/img/dancing/testing-command2.png)
  
  Now the next step is to see what shares are accessible. We do so by using the command `smbclient //target_IP/share_name -N`. Here it is important to reuse the `-N` switch since it will allow us to access shares without a password. First I attempt to access the shares that look interesting such as ADMIN$ and C$ these could hold important files. However, they are password protected and access fails.
  ![](/assets/img/dancing/failed-access.png)
  
  Up next are the shares called IPC$ and WorkShares. I get access to IPC$ but it has no viewable contents so it is not very useful to us. 
  ![](/assets/img/dancing/no-ls.png)
  
  Up next I attempt to access WorkShares and BINGO! We obtain access and it contains directories with files in them. 
  ![](/assets/img/dancing/get-flag.png)
  
  Here our job is basically done we have obtained the flag and we know that this share is not password protected so if I was an attacker I would snoop around to see if there are files containing sensitive info, upload malicious scripts, etc.  
  
- **Analysis:**  This box has many similarities with the previous one (Fawn) where we needed to access the FTP service running on a Linux machine. This is not a coincidence since SMB also acts as a file transmission protocol but on Windows machines it actually does much more and it has a wider attack surface. The main issue with SMB was that it allows null-session access, meaning no credentials were needed. This box got me in through a misconfiguration (anonymous null-session access), but it is worth noting that SMB’s wider attack surface also includes outright vulnerabilities. The most infamous is EternalBlue ([CVE-2017-0144](https://nvd.nist.gov/vuln/detail/cve-2017-0144)), a flaw in SMBv1 that allowed remote code execution and powered the 2017 WannaCry ransomware attack, which hit over 200,000 machines worldwide. The lesson there was not that the victims ran old systems (many ran supported, current ones) but that a patch had shipped two months earlier and a legacy protocol (SMBv1) was still enabled. Same theme as this box: SMB left exposed when it should not have been, just a vulnerability instead of a misconfiguration.
  
- **Remediation:** So how do we fix it, and how would we have caught it in the first place?
  The key mindset is to think like an attacker and scan your own network before someone else does. The same enumeration that got me into this box (an `nmap` scan finding an exposed SMB port, then probing the shares) is exactly what a defender should run against their own infrastructure to find these exposures first.
1. Proactively enumerate and port scan your own network to catch an exposed SMB port (445/139) or an anonymously accessible share before an attacker does.
2. Disable anonymous/null-session access to shares (`RestrictNullSessAccess`, disable the guest account).
3. Apply least-privilege share and NTFS permissions so a share like `WorkShares` isn’t readable by anyone.
4. Don’t expose SMB (445) to untrusted networks, and enable SMB signing.
5. Legacy systems and protocols should be patched if they cannot be disabled outright. 
  
- **Takeaways:** The biggest takeaway is how similar the enumeration-to-access process is from one service to the next. The pattern barely changes: run an `nmap` scan to find the service, use a search engine to get familiar with the client’s command syntax, test the switches to see what they actually do, and once you are in, use `help` to learn how to move around. Meow, Fawn, and now Dancing each followed this same loop with a different protocol every time, which is the real skill these boxes are building.
