- **Enumeration:** The typical starting point of enumerating a system is to conduct a Nmap scan of the system. Nmap is very useful for finding active services running on any machine all we have to do is point Nmap to the IP (Internet Protocol) address of the machine we want to enumerate. 
  ![](/assets/img/meow/nmap-scanning.png)
  
  As we can see from the screenshot Nmap was able to find a service running on the target machine. The service running is telnet and it is running on port number 23 and it is using the protocol TCP (Transmission Control Protocol). 
  
- **Access:** Now that we know what services are running on the target machine we can use this knowledge to take advantage of any misconfigurations to obtain access to the machine. In this case we will attempt to use any misconfigurations, weak or no passwords to gain access. To do so we simply point telnet to the target machines IP. 
  ![](/assets/img/meow/telnet-access.png)
  
  We have successfully connected to the target machine using telnet and it is now asking for a username. Here what we want access to is the root user account which is a privileged user account also known as superuser account. The root user account has UID (User ID) 0 which means it has full control over the machine and since root is literally the name of this user in Linux/Unix operating systems this should be our first try. 
  ![](/assets/img/meow/root-access.png)
  
  As  we can see from the screenshot we gained access to the machine and we can confirm it by looking at what the command line is displaying `root@Meow:~#`. This basically tells us that we are logged in as user `root` on the machine `Meow` which is what we wanted. 
  
  From here if we were a malicious actor we can do a number of things such install malware/viruses, setup cronjobs with malicious scripts, exfiltrate important user information, etc.
  
- **Analysis:**  So why did this work? Well the answer lies in two issues. 
1. Using telnet as a remote access protocol. 
	Telnet is a very old protocol for gaining remote access to a terminal and it does all of this without encryption or authentication. Telnet simply hands off the login portion to the OS (Operating System) and sends everything (even password) in plaintext. This is why telnet is no longer used. For example if I was a malicious actor and I was performing a MITM (Man In The Middle) attack I would be able to capture everything that telnet is sending in the packets and since nothing is encrypted I would be able to see every single character that was transmitted. 
2. OS root access misconfiguration.
	Forgetting to setup a password for the superuser account ends up exactly like in this HTB (Hack The Box) lab. It gives a malicious actor unlimited access to your machine. This is why as a defender it is always important to make sure that superuser/root accounts always use strong passwords. 
	
- **Remediation:** How do we prevent this from happening?
1. We NEVER use telnet as a remote access protocol as we saw telnet hands off login credentials to the OS without encryption and this means that user input can be sniffed and captured by an attacker inside the network. 
2. We make sure that the superuser/root account have strong passwords setup.
3. Instead of using telnet use SSH (Secure Shell) to connect remotely to a server. SSH by default encrypts all communication between client and server and thus even if an attacker was capturing all network traffic they would have no way of knowing the contents of the packets. 
- **Takeaways:** This HTB Lab highlights that weak/no credentials and using outdated remote access protocols can be a liability for system administrators. As a defender default to using more secure protocols like SSH. As an attacker look for services that are outdated or misconfigured to exploit weaknesses.
