- **Box Info:** 
	- Tier: 0
	- Name: Dancing
	- OS: Windows
	- Difficulty: Very Easy
- **Enumeration:** The first thing we do is run a scan on the target computer using Nmap this has become the standard procedure for these kinds of boxes. 
  ![](/assets/img/dancing/nmap-scan.png)
  
  The scan reveals several services on the target machine. The service we want to target is SMB (Server Message Block) and it uses port 445 over TCP. Thus, we can ignore the other services and we can focus on the service called `microsoft-ds`. 
  
- **Access:** After doing a quick search on DuckDuckGo I find what command options I can use with the `smbclient` command and one stands out to me.  
  ![](/assets/img/dancing/command-search.png)
  
  The `-L` switch combined with `-N` will allow us to list the shares without prompting us for a password but I still mess around with the switches to see what they do. As the saying goes "trust but verify". As expected `-L` switch without `-N` allows us to list the shares but it prompts for a password. Lucky for us there is no password and we simply press `ENTER` on the blank password field. 
  ![](/assets/img/dancing/testing-command1.png)
  
  Then I test `-L` + `-N` and as expected we get a list of the shares without a password prompt.
  ![](/assets/img/dancing/testing-command2.png)
  
  Now the next step is to see what shares are accessible. We do so by using the command `smbclient //target_IP/share_name -N`. Here it is important to reuse the `-N` switch since it will allow us to access shares without a password. First I attempt to access the shares that look interesting such as ADMIN$ and C$ these could hold important files. However, they are password protected and access fails.
  ![](/assets/img/dancing/failed-access.png)
  
  Up next are the shares called IPC$ and WorkShares. I get access to IPC$ but it has no viewable contents so it is not very useful to us. 
  ![](/assets/img/dancing/no-ls.png)
  
  Up next I attempt to access WorkShares and BINGO! We obtain access and it contains directories with files in them. 
  ![](/assets/img/dancing/get-flag.png)
  
  Here our job is basically done we have obtained the flag and we know that this share is not password protected so if I was an attacker I would snoop around to see if there are files containing sensitive info, upload malicious scripts, etc.  
  
- **Analysis:**  This box has many similarities with the previous one (Fawn) where we needed to access the FTP service running on a Linux machine. This is not a coincidence since SMB also acts as a file transmission protocol but on Windows machines it actually does much more and it has a wider attack surface. The main issue with SMB was that it allows null-session access, meaning no credentials were needed. 
  
- **Remediation:** So How do we fix it? 
1. Disable anonymous/null-session access to shares (`RestrictNullSessAccess`, disable the guest account).
2. Apply least-privilege share and NTFS permissions so a share like WorkShares isn’t readable by anyone.
3. Don’t expose SMB (445) to untrusted networks, and enable SMB signing.
  
- **Takeaways:** The biggest takeaway here is how the process of enumeration to access is very similar from service to service. The use of Nmap, using search engines to become familiar with the command syntax, testing different commands and once you have access to the service using the command 'help' to understand how to move around.
