CS student at Cal Poly Pomona working toward application security and security engineering. I'm interested in the judgment heavy end of the field, where security meets low-level systems: memory, OS internals, and how things actually execute underneath. Not just whether a system can be broken into, but why it was breakable, what the real root cause was, and how you'd design it so the mistake can't happen again.

These are writeups from HackTheBox labs and personal security lab work. The focus is less on logging commands and more on the mechanism behind each finding. The question I keep asking myself is "how could someone misuse this in ways the designer didn't intend?"
